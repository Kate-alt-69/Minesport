# Page 13 — Minecraft Light Blocks in Blender

This page explains Minesport's Minecraft-style light placement **from the beginning**. If you do not know where the Minesport sidebar is, read **[Page 11](11.md)**. If clicking FLATTER blocks is still confusing, read **[Page 12](12.md)** first.

## The two objects involved

Minesport deliberately separates the Minecraft concept from the Blender renderer:

```text
MINESPORT_LIGHT_BLOCK_LVL_<level>_...
└─ 1×1×1 helper cube showing the Minecraft light voxel

Minesport_UserLight_...
└─ Blender POINT light that actually illuminates the scene
```

The helper cube is not the thing producing light. It is a viewport guide showing which Minecraft-sized voxel owns the light source.

The Blender POINT light is the actual emitter.

This separation is important because hiding the helper must **not** turn off illumination, and hiding Minesport light helpers must **not** hide every normal Blender light/camera/empty.

## Where the controls are

1. In Blender, move the mouse over the **3D Viewport**.
2. Press **N**.
3. Click the **Minesport** tab.
4. Select a Minesport `FLATTER_...` object.
5. Open the **FLATTER Workflow / Minecraft Light Block** controls.

If step 3 makes no sense, use **[Page 11 — Find the Minesport Panel](11.md)**.

## Place a light above a block

1. Stay in **Object Mode**.
2. Click the **top surface** of the logical Minecraft block where the light should be placed.
3. Confirm the block gets the Minesport green logical outline/focus.
4. In the Minesport FLATTER panel choose the desired **Light Level** from 1 to 15.
5. Choose **Top face** if it is not already selected.
6. Click **Place 1×1×1 Light Block**.

Minesport places the light in the **center of the adjacent Minecraft voxel**, not directly on the clicked face. For a top-face placement, the emitter/helper therefore occupies the block-sized cell above the clicked block.

## Bottom and center placement

The snap option can be:

- **Top face** — adjacent voxel above the focused Minecraft block.
- **Bottom face** — adjacent voxel below it.
- **Block center** — center of the focused block's voxel.

When Minesport remembers a top/bottom face from your viewport click, the snap control follows that face where possible.

## What the light level means

Minesport stores the original logical Minecraft block-light level, from **1 to 15**.

The Blender light then gets smooth renderer-friendly falloff/range while preserving the logical level as Minesport metadata. This means Blender can look smooth instead of trying to render Minecraft's literal stair-step light propagation.

## Show/hide the 1×1×1 helpers

The helper objects use names beginning with:

`MINESPORT_LIGHT_BLOCK_LVL_`

The Minesport helper visibility control only targets these Minesport helper cubes. It does **not** use Blender's global `Show Extras` switch, so normal lights, cameras, armatures, and unrelated helper structures stay visible.

The actual POINT lights continue illuminating even when their 1×1×1 helper cubes are hidden.

## Find the light in the Outliner

Open Blender's Outliner and search for:

- `MINESPORT_LIGHT_BLOCK_LVL_` to find the 1×1×1 helper;
- `Minesport_UserLight_` to find user-created emitters;
- imported Minecraft light names such as torch/wall-torch light objects for lights restored from the export.

## Imported Minecraft torches vs user Light blocks

An exported torch, lantern, furnace, candle, etc. can already create/restore a Blender light from Minesport export metadata. Those source lights are not the same thing as a user-created invisible Minecraft `light` block.

The `MINESPORT_LIGHT_BLOCK_LVL_...` helper naming is specifically for Minesport's invisible/light-block-style helper representation.

## If the light looks wrong

Check:

1. the POINT light is actually enabled in the Outliner;
2. you are viewing a Blender shading/render mode where scene lights affect the view;
3. the light is centered in the intended Minecraft voxel;
4. helper visibility is not being confused with actual light visibility;
5. the selected Light Level is what you expected.

For broader problems, use **[Page 20 — Troubleshooting](20.md)**.
