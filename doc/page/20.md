# Page 20 — Troubleshooting

This page is for problems after you have already tried the normal workflow. If a term below is unfamiliar, follow the linked beginner page instead of guessing.

## I cannot find the Minesport panel in Blender

Read **[Page 11 — Find the Minesport Panel](11.md)**. The exact path is:

**3D Viewport → press N → Minesport tab**.

If the tab is missing, verify the `Minesport Dynamic Translator` addon is installed and enabled, then restart Blender after updating the addon.

## I selected a FLATTER object but clicking does not give me a green block outline

Read **[Page 12 — FLATTER for Blender Beginners](12.md)** first.

Then check:

1. Blender is in **Object Mode**.
2. The addon reports version **0.2.0 or newer**.
3. The active object is actually a Minesport `FLATTER_...` or `FLATTER_SHAPE_...` object.
4. **Logical overlay** is not set to `Off`.
5. Nothing unrelated is physically in front of the FLATTER surface you are clicking.
6. Restart Blender if the addon was updated while Blender was already open.

Normal LMB should address the logical block under the cursor. Shift adds to the logical selection; Ctrl removes; Alt deliberately passes the click back to Blender.

## The entire FLATTER object has grid lines everywhere

You probably enabled **Logical overlay → Full cell**. That is a diagnostic view, not the normal selection appearance.

Use **Logical overlay → Selected only** for normal work.

## I do not understand why thousands of Minecraft blocks are one Blender object

That is the point of FLATTER. Read **[Page 12](12.md)**. The visible mesh is optimized render geometry; the original Minecraft block grid remains embedded and addressable.

## I need one block to behave like a normal Blender object

Use FLATTER **Materialize** for that block. Do not destroy the entire optimized FLATTER mesh just to animate one block.

See the **Materialize** section on **[Page 12](12.md)**.

## My Minecraft Light block is invisible / I cannot find it

Read **[Page 13 — Minecraft Light Blocks in Blender](13.md)**.

Search the Outliner for:

- `MINESPORT_LIGHT_BLOCK_LVL_` — the 1×1×1 viewport helper;
- `Minesport_UserLight_` — the actual Blender POINT light created by the user-placement tool.

The helper and emitter are intentionally separate objects.

## Hiding Minesport light blocks should not hide every Blender light

Correct. Minesport 0.2.0 helper visibility is supposed to affect only objects whose helper identity/prefix belongs to the Minesport light-block system. It must not toggle Blender's global `Show Extras` setting.

If regular Blender lights/cameras/empties disappear when you hide Minesport Light Blocks, report it as a bug and include your addon version.

## The light exists but I do not see illumination

Check Blender's viewport shading. Some viewport modes do not use scene lights the way Rendered/scene-light modes do.

Also verify the actual POINT light is enabled in the Outliner; hiding the 1×1×1 helper cube should not disable illumination.

## Runtime Model Cache takes time the first time

That is expected for a new Minecraft version/mod-set fingerprint. Minesport starts an isolated exact-version Fabric client worker, captures registry/model data, writes a reusable cache, and reuses it until the relevant mod/version fingerprint changes.

See **[Page 90 — Runtime Model Cache](90.md)** for the full explanation.

## A helper mod such as Crash Assistant opens during cache generation

That is not desired. The runtime worker is not a normal player game session. Minesport specifically excludes Crash Assistant from the disposable registry worker because it can misinterpret the intentionally short-lived worker as a crashed game.

If another non-content helper mod causes the same problem, include the mod name and worker diagnostics in the bug report rather than deleting random content mods from the worker.

## The Minesport desktop UI looks frozen but Windows does not say “Not Responding”

Collect diagnostics. Minesport 0.2.0 batches engine-log UI redraws instead of rebuilding the debug-console widget for every resolver line, but another long synchronous operation may still reveal a bug.

Do not assume zero CPU means the process is dead; include timestamps around when input stopped responding and when it resumed.

## Where are diagnostics stored?

On Windows, normal Minesport diagnostics use the application data root:

`%LOCALAPPDATA%\kastrick's_software\minesport\diagnostics\`

Rebuildable caches belong under the user cache tree rather than beside durable settings:

`%USERPROFILE%\.cache\kastrick's_software\minesport\`

## What to include in a useful bug report

Include:

- Minesport version;
- Blender addon version if Blender is involved;
- Minecraft version;
- loader (Fabric/Quilt/Forge/NeoForge/etc.);
- exact action you clicked;
- what you expected;
- what happened instead;
- relevant screenshot;
- Minesport diagnostics log;
- runtime-worker log if the model-cache worker failed.

Avoid sending an entire Minecraft world unless it is actually needed to reproduce the bug.
