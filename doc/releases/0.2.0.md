# Minesport 0.2.0 — Official “bug-free*” Release

Minesport 0.2.0 is the first release in the 0.2 line intended to feel like one coherent Minecraft → DCC workflow instead of a pile of exporter experiments.

> **bug-free\*** — *the goal is a release without known show-stopper bugs after current testing, not a mathematically enforceable promise that no bug exists anywhere. If you find one, congratulations: you found the asterisk. Please report it with diagnostics.*

## Highlights

### FLATTER 0.2 workflow

- FLATTER keeps Minecraft blocks as an embedded logical voxel grid while compiling compatible visible geometry into much lighter Blender meshes.
- Full SOLID geometry and compatible repeated non-full SHAPE geometry are kept in separate FLATTER streams.
- FLATTER cell/object size is configurable: 8³, 16³, 32³, or 64³.
- Blender can directly address logical FLATTER blocks with viewport clicks instead of requiring a hidden/undiscoverable edit-mode ritual.
- Logical selection uses a strong green 1×1×1 outline.
- Select, Inspect, Box Select, Materialize, selection sets, and Liquid Merge workflows remain available.

Beginner guide: **[Page 12 — FLATTER for Blender Beginners](../page/12.md)**.

### Minecraft lights in Blender

- Minecraft light metadata exports into Blender-native lighting.
- User-created Minecraft Light blocks use a dedicated 1×1×1 `MINESPORT_LIGHT_BLOCK_LVL_<level>` viewport helper.
- The actual illumination comes from a separate Blender POINT light.
- Hiding Minesport Light-block helpers no longer toggles Blender's global Extras visibility and therefore must not hide unrelated cameras/lights/empties.
- Top/bottom/center placement is aligned to Minecraft-sized voxels.

Beginner guide: **[Page 13 — Minecraft Light Blocks in Blender](../page/13.md)**.

### Runtime model registry/cache

- Supported Fabric exports can automatically prepare an exact-version runtime model cache.
- The worker loads Minecraft's own registered/baked block model information from an isolated disposable runtime rather than launching the user's normal game profile.
- Exact Minecraft/mod fingerprints allow reuse until relevant inputs change.
- Registry caches store geometry/state/texture identifiers, not duplicate texture image payloads.
- Crash Assistant is excluded from the disposable worker so it does not misinterpret intentional worker exit as a player-session crash.

Details: **[Page 90 — Runtime Model Cache](../page/90.md)**.

### Desktop workflow cleanup

- The unwanted Minesport **Project** file/workspace system was removed.
- The separate Asset Resolution Center navigation/popup was removed; asset/resolver controls live in Settings.
- Manual Preflight is an Advanced diagnostic rather than a mandatory Export-page wall of text.
- Optimization in Export is reduced to a compact status/action, with details routed through task notifications/diagnostics.
- Runtime-model cache generation is part of Export when needed; manual cache tools remain in Advanced settings.
- Engine log bursts are batched to reduce Fyne UI starvation.
- Resolver activation respects the selected loader instead of scanning a Fabric pack again as Quilt and Forge.

### Paths/cache cleanup

Durable application data and rebuildable caches are separated. On Windows the intended roots are:

- `%LOCALAPPDATA%\kastrick's_software\minesport\` — durable settings/diagnostics;
- `%USERPROFILE%\.cache\kastrick's_software\minesport\` — rebuildable caches/workspaces/toolchains.

### Beginner documentation

0.2.0 introduces the repository-backed `/doc/` manual and an in-app Documentation browser. Documentation/video media can be updated on GitHub without bloating every Minesport installation.

Start with **[Page 01 — Start Here](../page/01.md)**.

## Compatibility direction

The Fabric Bridge compatibility recipe system covers the supported 1.19.x → 1.21.x families plus 26.x profiles currently represented in the compatibility manifest. Patch recipes are tested against current canonical Bridge sources so source-line movement is less likely to silently break an older target.

Compatibility remains version/API dependent; a recipe being present does not mean every third-party mod uses only vanilla baked-model paths.

## Known rough edges worth reporting

0.2.0 intentionally keeps diagnostics for unresolved/unsupported model paths rather than silently inventing geometry. Custom renderers, version-specific model changes, and unusual multipart/transparency behavior can still expose cases that need additional resolver/runtime handling.

When reporting one, include the Minecraft version, loader, relevant mod names, exact block/state if known, screenshot, and Minesport diagnostics log. See **[Page 20 — Troubleshooting](../page/20.md)**.
